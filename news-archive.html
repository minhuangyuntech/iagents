追蹤版本的方法

  • 先讀 news.html 抓當日最重要的工程主題，再記下它屬於 official commit、release 還是外部報導。
  • 再往前看每日檔案，追蹤同一主題是否連續出現。
  • 每月檔案適合拿來整理版本節奏與產品方向變化。
  • 做簡報時可挑 3 天以上的消息，形成一條演進時間線。
  • 做課堂比較時，可固定用「source / control boundary / 驗證方法 / first wrong write」四欄整理，較容易把消息轉成工程問題。
  • 若消息提到 approval、deny fallback 或 slash command routing，固定再問：誰有權放行、拒絕後剩哪些合法路徑、最後寫回哪個 session。
  • 若消息提到 interactive prompt 或 relay，固定再補一欄「誰收到 ack、何時收到、哪裡留痕」，避免只看畫面有沒有跳出提示。
  • 若消息提到圖示、模型清單、chat type 或安裝流程，固定再分開記 visible affordance、真正 authority 與殘留 state，避免把 UI 提示誤看成系統已完成。
  • 若消息提到 autocomplete、Enter 或設定儲存，固定再分開記「使用者原始意圖」與「UI 最後接受的值」，避免把介面代填誤看成正確需求。
  • 若消息是模型升級或新能力新聞，固定再補一欄 routing / cost / latency 影響，避免把外部報導直接當成部署結論。
